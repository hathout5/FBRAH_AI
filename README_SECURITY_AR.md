# حقيبة FBRAH AI — تقوية الأمن والحسابات

## 1) محتويات الحقيبة

| الملف | الامتداد | الوظيفة |
|---|---|---|
| `app.py` | `.py` | نسخة كاملة من ملف التطبيق بعد دمج طبقة الحماية وتعديلات المسارات والسياسات الواردة في هذه الحقيبة. |
| `templates/index.html` | `.html` | نسخة كاملة من الواجهة بعد تحويل تسجيل الخروج إلى POST. |
| `security_hardening.py` | `.py` | وحدة مستقلة للحماية من CSRF، ورؤوس الأمان، وتحديد محاولات الدخول، واستعادة كلمة المرور بالبريد. |
| `INSTALL_RELEASE.ps1` | `.ps1` | مثبت PowerShell 5.1 يطبق التغييرات على نسخة المشروع الحالية مع نسخ احتياطية. |
| `test_release_integrity.py` و`test_index_integrity.py` و`test_priority_smoke.py` | `.py` | اختبارات ثابتة لا تشغّل خادم Flask ولا تفتح قاعدة بيانات المستخدم. |
| `ENV_SECURITY.example` | `.example` | إعدادات SMTP ورابط الموقع العام؛ لا يحتوي على أسرار حقيقية. |
| `MANIFEST_SHA256.txt` | `.txt` | بصمات SHA-256 لملفات الحقيبة. |

## 2) نطاق الحماية المطبقة

- إضافة CSRF synchronizer token إلى صفحات HTML والنماذج، وإلى طلبات `fetch` ذات المصدر نفسه وطرق POST/PUT/PATCH/DELETE.
- رفض الطلبات المغيّرة للبيانات إذا غاب رمز CSRF أو لم يطابق جلسة المستخدم.
- السماح المحدود بـ `sendBeacon` الخاص بقياس الواجهة فقط عند وجود Origin مطابق للمصدر نفسه؛ لا يُقبل Origin خارجي.
- إضافة رؤوس `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`، وإضافة HSTS فقط عند HTTPS.
- تقييد محاولات تسجيل الدخول لكل عنوان IP ولكل معرّف حساب، مع حظر مؤقت بعد تكرار الفشل.
- إضافة استعادة كلمة المرور عبر رابط عشوائي قوي، مخزن في قاعدة البيانات على هيئة SHA-256 فقط، صالح 20 دقيقة ولمرة واحدة، مع إبطال الروابط السابقة بعد إصدار رابط جديد.
- عدم كشف ما إذا كان اسم المستخدم/البريد موجوداً؛ استجابة طلب الاستعادة موحدة.
- لا تُرسل روابط الاستعادة إلا عند ضبط `FBRAH_PUBLIC_BASE_URL` ورابط HTTPS قانوني (يسمح HTTP لـ localhost فقط) وبيانات SMTP.
- لا يتم تخزين كلمة المرور الجديدة إلا بعد التحقق من صلاحية الرمز، ثم تُهَشّ باستخدام دالة التطبيق الحالية `hash_password`.
- رفع الحد الأدنى لكلمات المرور الجديدة في التسجيل وتغيير كلمة المرور والإدارة إلى 12 حرفاً.
- تسجيل الخروج أصبح POST فقط؛ ومسح المحادثة وتصدير التسجيلات لم تعد تقبل GET.
- إخفاء رمز إعادة التعيين من سجلات HTTP.
- جعل القيم الافتراضية للانتقال التلقائي بين نماذج السحابة والمحلية `0`، مع احترام القيم الصريحة في `.env`.

## 3) تغيير اسم المستخدم وكلمة المرور

ميزة تغيير اسم المستخدم وكلمة المرور موجودة بالفعل في صفحة `/account` في النسخة الأصلية. الحقيبة تشدد سياسة كلمة المرور الجديدة إلى 12 حرفاً وتضيف مسار استعادة كلمة المرور من صفحة الدخول. تغيير اسم المستخدم لا يزال يمر عبر منطق الحساب الأصلي وقيود التفرد في SQLite. حساب `admin` لا يُعاد تسميته من صفحة الحساب وفق السياسة الحالية.

## 4) إعداد البريد لاستعادة كلمة المرور

1. انسخ القيم المناسبة من `ENV_SECURITY.example` إلى ملف `.env` المحلي يدوياً.
2. اضبط `FBRAH_PUBLIC_BASE_URL` على عنوان الموقع الحقيقي مع HTTPS في بيئة الإنتاج.
3. اضبط SMTP host/port/from/user/password وفق مزود البريد.
4. لا ترسل ملف `.env` إلى أي شخص ولا تضفه إلى Git.
5. أعد تشغيل Flask بعد تعديل البيئة.

إذا لم يُضبط SMTP أو الرابط العام، ستظل صفحة طلب الاستعادة تعرض رسالة موحدة، لكن لن يصل بريد. لا توجد آلية تجاوز أو إظهار الرمز في الشاشة أو السجلات.

## 5) طريقة التطبيق الآمنة

### الخيار الموصى به: المثبت

1. خذ نسخة احتياطية مستقلة من المشروع وقاعدة البيانات و`data` و`.env` وملفات Qdrant والتسجيلات.
2. فك الحقيبة كاملة في مجلد مؤقت، ولا تنقل ملفاتها يدوياً إلى جذر المشروع.
3. افتح PowerShell 5.1 داخل مجلد الحقيبة.
4. شغّل المثبت مع مسار المشروع الصحيح:

```powershell
powershell -ExecutionPolicy Bypass -File ".\INSTALL_RELEASE.ps1" -ProjectRoot "C:\مسار\مشروعك"
```

ينشئ المثبت نسخة سابقة من الملفات التي سيستبدلها في `.fbrah_release_backup_<timestamp>` قبل الكتابة. لا ينفذ أوامر Git ولا يغيّر `.env` أو قاعدة البيانات أو مجلد `data` أو Qdrant.

### خيار استبدال الملفات الكاملة

يمكنك استبدال `app.py` و`templates/index.html` بنظيريهما داخل الحقيبة، لكن لا تفعل ذلك إلا بعد التأكد أن مشروعك المحلي يطابق النسخة التي بُنيت عليها الحقيبة. إذا كان لديك تعديلات أحدث غير موجودة في الملف المرفق، استخدم المثبت أو اطلب دمجاً مخصصاً بدلاً من الاستبدال.

## 6) التحقق بعد التطبيق

من جذر المشروع وبعد تفعيل البيئة الافتراضية:

```powershell
python -m py_compile app.py backup_db.py restore_db.py reset_admin.py security_hardening.py fbrah_priority_enhancements.py
python -m unittest -v test_release_integrity.py test_index_integrity.py
python test_priority_smoke.py
```

ثم اختبر يدوياً:
- تسجيل الدخول الصحيح والخاطئ.
- تسجيل الخروج من الواجهة.
- التسجيل الجديد بكلمة مرور 12 حرفاً على الأقل.
- تغيير كلمة المرور واسم المستخدم من `/account`.
- طلب استعادة كلمة المرور لبريد موجود وغير موجود؛ يجب أن تكون الرسالة متطابقة.
- وصول البريد، انتهاء صلاحية الرابط، عدم إمكان استخدام الرابط مرتين.
- تجربة POST بدون CSRF ويجب رفضه، وتجربة النموذج الطبيعي ويجب نجاحه.
- اختبار التسجيلات والتصدير ومسح المحادثة والملفات بعد الدخول بحسابين مختلفين.

## 7) حدود مهمة — ما لم يُعتمد بعد

هذه الحقيبة تعالج طبقة جلسات/CSRF/استعادة كلمة المرور وبعض طرق HTTP، لكنها **لا تعني أن المشروع أصبح مدققاً بالكامل أو آمناً إنتاجياً بمجرد تثبيتها**. يجب استكمال واختبار النقاط التالية على بيئة تجريبية ببيانات غير حقيقية قبل الإنتاج:

- عزل مسارات ملفات التسجيلات والتحقق من `realpath/commonpath` في جميع عمليات القراءة والنسخ والحذف والتنزيل، وإزالة البحث الجزئي عن `rid` الذي قد يطابق تسجيل مستخدم آخر.
- جعل فهرس التسجيلات JSON ذريّ الكتابة والتحقق من كل عنصر قبل استخدامه، وعدم إرجاع مسارات الخادم المطلقة للمستخدم.
- استبدال بناء HTML الخاص بقائمة التسجيلات بـ DOM API و`textContent` وإزالة inline event handlers.
- فصل التشخيص للقراءة فقط عن الإصلاح، وعدم حذف ملفات تلقائياً، وقصر الإصلاح على المدير مع سجل تدقيق ونسخة احتياطية.
- تضييق صلاحيات `/api/self_heal` و`/api/system_diagnostics` و`/api/recordings/where` إلى المدير، ومراجعة كل مسار إدارة.
- تحديد أحجام JSON وBase64 وOCR وعدد بكسلات الصور، وعدم كشف رسائل الاستثناء والمسارات المطلقة.
- مراجعة `log_terminal` وقياس الواجهة لمنع تسجيل محتوى الأسئلة/النص المنطوق أو الأسرار.
- اختبار تكامل فعلي مع SMTP وHTTPS، ومراجعة إعدادات reverse proxy و`TRUSTED_HOSTS` وقيود الشبكة قبل نشر عام.

لا يُنصح بنشر التطبيق على الإنترنت قبل معالجة هذه النقاط. لا تضع مفاتيح API أو كلمات المرور في GitHub. لم تتضمن الحقيبة `.git` أو `.env` أو قواعد بيانات أو Qdrant أو التسجيلات.

راجع `OLLAMA_TROUBLESHOOTING_AR.md` لتشخيص اختفاء النماذج. أضيف زر لإعادة اكتشاف Ollama؛ ويختار التطبيق Gemini عند توفر مفتاحه والإنترنت، وQwen المحلي عند انقطاع الإنترنت إذا كان مثبتاً. لا يثبت ذلك صلاحية مفتاح Gemini أو الحصة، ولا يسمح بانتقال تلقائي بين المحلي والسحابي.

## 8) التراجع

أوقف Flask، ثم أعد `app.py` و`templates/index.html` من المجلد الذي أنشأه المثبت داخل `.fbrah_release_backup_<timestamp>`. احتفظ بـ `security_hardening.py` أو احذفه بعد إعادة الملفات الأصلية. لا تحذف قاعدة البيانات؛ جداول `fbrah_password_reset_tokens` و`fbrah_auth_throttle` إضافية ولا تمس جداول المستخدمين الحالية.

## 9) ملاحظة تشغيلية

لا يحتوي هذا الإصدار على ترحيل أو تعديل لبيانات المستخدمين الحالية، ولا يفرض تغيير كلمات المرور القديمة فوراً. سياسة 12 حرفاً تنطبق على كلمات المرور الجديدة/المعدلة. إعادة تعيين كلمة المرور تحتاج بريداً صالحاً مرتبطاً بالحساب.


## ملاحظة إصدار لاحق
هذه الوثيقة مرجع أمني مساعد. مثبت الإصدار في هذه الحزمة هو `INSTALL_RELEASE.ps1`. الاختبارات القديمة والسكريبتات غير المعتمدة غير مدرجة في ZIP. راجع `RELEASE_GUIDE_AR.md` لمعرفة ما تم تنفيذه وما لم يُعتمد بعد.

## مهلة مزودي النماذج السحابية

- `FBRAH_CLOUD_TIMEOUT=30` هي المهلة الافتراضية لقراءة استجابة مزود النموذج السحابي.
- يحصر الكود القيمة بين 10 و60 ثانية، ويستخدم مهلة اتصال مستقلة قدرها 5 ثوانٍ.
- إعدادات الحزمة النموذجية تفعّل التحويل داخل المسارين المستقلين: `FBRAH_ALLOW_CLOUD_FALLBACK=1` و`FBRAH_ALLOW_LOCAL_MODEL_FALLBACK=1`.
- التحويل السحابي محصور بين Gemini وGROQ والموديلات المحددة صراحةً لكل مزود؛ والتحويل المحلي محصور في موديلات Ollama المثبتة فعلياً. لا يوجد انتقال تلقائي بين السحابي والمحلي في أي اتجاه.
- عند غياب متغيرات التحويل من البيئة، يظل افتراضي الكود مغلقاً (0). انسخ القيم المطلوبة إلى ملف `.env` المحلي دون رفعه إلى GitHub.
- أضيفت سجلات تشغيل تتضمن PID واسم المزود والموديل ورقم المحاولة وسبب التحويل، دون طباعة مفاتيح API.
