FBRAH AI — الحزمة الكاملة المرشحة للإصدار
========================================

هذه الحزمة مبنية على نسخة المشروع المرشحة للإصدار، وتضم تطبيق Flask والواجهات وأدوات قاعدة البيانات والحماية والاختبارات والوثائق. لا تحتوي على قاعدة بياناتك أو بيانات Qdrant أو ملف .env أو مفاتيح API.

1) محتويات الحزمة
-----------------
- app.py: تطبيق Flask ومسارات البحث وRAG وتوجيه النماذج.
- templates/index.html وtemplates/admin_users.html: الواجهة الرئيسية ولوحة الإدارة.
- security_hardening.py: CSRF وترويسات الأمان وتحديد محاولات الدخول واستعادة كلمة المرور بالبريد.
- backup_db.py وrestore_db.py وreset_admin.py: النسخ الاحتياطي والاستعادة وإعادة تعيين كلمة مرور المدير.
- requirements.txt وrequirements-rag.txt: المتطلبات الأساسية وإضافات RAG.
- .env.example وENV_SECURITY.example: عينات إعدادات بلا أسرار فعلية.
- .gitattributes و.gitignore: توحيد نهايات الأسطر ومنع رفع الملفات المحلية الحساسة.
- test_release_integrity.py: اختبارات ثابتة لا تستورد التطبيق ولا تفتح قاعدة البيانات.
- INSTALL_RELEASE.ps1: مثبت يتحقق من SHA-256 ويجهز الملفات مرحلياً ويحفظ نسخة سابقة ويتراجع عند فشل الاختبارات.
- MANIFEST_SHA256.txt: بصمات الملفات التي يتحقق منها المثبت.
- أدلة الإصدار والحماية وخطة RAG ومصفوفة الخصائص وسجل التعديلات وقائمة رفع GitHub الآمن وتنبيه مطابقة المصدر.

2) التثبيت الآمن على Windows / PowerShell 5.1
---------------------------------------------
1. اقرأ RECONCILIATION_REQUIRED_AR.md؛ أحجام ملفات المصدر في الحزمة تختلف عن سجل المجلد المحلي. لا تستبدل الملفات قبل مراجعة الفروق.
2. فك ضغط الحزمة في مجلد مستقل خارج مجلد المشروع.
3. افتح PowerShell في مجلد الحزمة وشغّل:

   powershell -ExecutionPolicy Bypass -File .\INSTALL_RELEASE.ps1 -ProjectRoot "C:\path\to\Fbrah Ai G"

4. يعرض المثبت الفرع وحالة Git وأحجام وبصمات الملفات الأساسية، ولا يبدأ إلا بعد كتابة APPLY. ثم يتحقق من كل بصمة SHA-256، ويشغل الاختبارات قبل الاستبدال، ويحفظ نسخة من كل ملف سيستبدله، ثم يثبت الملفات ويعيد الاختبار. عند فشل اختبار ما بعد التثبيت يستعيد الملفات السابقة تلقائياً.
5. لا ينسخ المثبت ولا يعدل .env أو قواعد البيانات أو مجلد data أو Qdrant أو النسخ الاحتياطية أو سجل Git.
6. احتفظ بمجلد النسخة السابقة حتى تنتهي من اختبار التطبيق.

3) إعداد البيئة والنماذج
-----------------------
- أنشئ .env محلياً بنسخ .env.example، ثم أدخل مفاتيحك بنفسك. لا ترسل .env ولا ترفعه إلى GitHub.
- اترك القيم التالية كما هي ما لم تطلب صراحةً تغيير سياسة التحويل:

   FBRAH_ALLOW_CLOUD_FALLBACK=1
   FBRAH_ALLOW_LOCAL_MODEL_FALLBACK=1
   GROQ_MODELS=openai/gpt-oss-120b  # أضف معرفات GROQ المتاحة لحسابك مفصولة بفواصل
   FBRAH_CLOUD_TIMEOUT=30

- مهلة النماذج السحابية الافتراضية 30 ثانية، ويقيدها الكود بين 10 و60 ثانية.
- التحويل السحابي بين Gemini وGROQ والموديلات السحابية المهيأة، والتحويل المحلي بين نماذج Ollama المثبتة، مفعّلان بالإعدادات أعلاه. لا يوجد انتقال بين السحابي والمحلي في أي اتجاه.
- لا يحدث تنزيل لنماذج embeddings تلقائياً ما دام FBRAH_ALLOW_ONLINE_EMBED=0.

4) خصائص التطبيق الموجودة
-------------------------
- رفع وقراءة الملفات وصيغ PDF وDOCX وXLSX وPPTX وTXT وCSV والصيغ البرمجية المدعومة.
- البحث النصي BM25 والبحث المتجهي وإعادة ترتيب النتائج عند توفر النماذج اللازمة.
- معالجة ملف مستهدف حصرياً، مع التحقق من ملكية المستخدم والمسار ضمن مسارات الحماية القائمة.
- توليد المستندات والتصدير، ولوحة القلم والتعرف على الكتابة، وتعدد الأدوار الحوارية.
- موجز الأخبار RSS مع اسم الناشر ورابط الخبر وعرض DOM آمن.
- شريط الأخبار بثلاث مدد دورة: 270 ثانية (بطيء جداً)، 240 ثانية (بطيء)، 210 ثانية (متوسط)، مع الإيقاف والاستئناف والإخفاء والاستعادة. تفضيلات V1 القديمة تهاجر إلى V2 مع الحفاظ على الإخفاء والإيقاف.
- زر الصوت/النداء يستخدم حالة التفعيل الكحلية والذهبية، مع احترام إذن الميكروفون وسياسات المتصفح.

5) تثبيت المتطلبات والاختبارات
------------------------------
إذا كنت تنشئ بيئة افتراضية جديدة:

   py -3 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   pip install -r requirements-rag.txt

ثم شغّل:

   python -m unittest -v test_release_integrity.py

الاختبارات الحالية ثابتة؛ لا تستدعي مزودي النماذج ولا تفتح قاعدة البيانات. وقد تم أيضاً فحص Python AST وJinja وJavaScript داخل الحزمة. يلزم اختبار التشغيل الفعلي على نسخة قاعدة بيانات تجريبية قبل الاعتماد.

6) ما لم يثبت بعد
-----------------
لم يتم في هذا التسليم إثبات التشغيل الإنتاجي أو إجراء اختبار اختراق. يلزم اختبار منفصل لـ Flask والجلسات وCSRF وSMTP وOCR وPDF العربي والرفع الكبير وQdrant ومزودي Gemini/GROQ/Ollama وجودة RAG على مجموعة أسئلة قانونية مرجعية. راجع FINAL_AUDIT_AR.md وFEATURE_MATRIX_AR_EN.md وRAG_QUALITY_ROADMAP_AR_EN.md وGITHUB_PUBLISH_CHECKLIST_AR.md وRECONCILIATION_REQUIRED_AR.md.

7) قواعد GitHub والأمان
----------------------
- لا ترفع .env أو قواعد البيانات أو ملفات WAL/SHM أو data/ أو Qdrant أو backups/ أو السجلات أو .venv أو مجلدات النسخ الاحتياطية الناتجة عن المثبت.
- راجع git status --short وgit diff --check وgit diff قبل staging.
- لا تستخدم git add -A قبل مراجعة الملفات غير المتتبعة والملفات المتجاهلة.
- لا تستخدم git push --force ولا تحذف أو تدمج الفروع ذات التاريخ المنفصل دون خطة مستقلة.
- جعل المستودع خاصاً أو حذف السر من الملف الحالي لا يزيل الأسرار القديمة من Git history. دوّر أي مفتاح أو كلمة مرور سبق كشفها، وراجع التاريخ بإجراء مستقل قبل إعادة النشر.
- لم تنفذ هذه الحزمة git add أو commit أو push.

هذه نسخة مرشحة للإصدار وليست شهادة اعتماد إنتاجي أو اجتياز اختبار اختراق.
